
# Security Policy

## Project status

BuildTrace is currently in pre-implementation development. There are no supported released versions yet.

## Reporting a vulnerability

Please do not report suspected vulnerabilities in public GitHub issues, discussions, pull requests or social posts.

Use GitHub's private vulnerability reporting feature from the repository's **Security** tab when it is available. If private reporting is not enabled, contact the repository maintainer privately through GitHub and request a secure reporting channel.

Include, where possible:

- A concise description of the issue and its potential impact.
- The affected commit, branch or component.
- Reproduction steps or a proof of concept that does not expose real user data.
- Any suggested mitigation.

Please do not include credentials, private project records or other sensitive user data in a report.

## Disclosure

Please allow the maintainers a reasonable opportunity to investigate and prepare a fix before publicly disclosing a vulnerability. The project will coordinate disclosure and any required security advisory when an issue is confirmed.

## Scope

Until a release is published, security reports concerning the repository, proposed architecture or development infrastructure are welcome. Acknowledgement and remediation timelines cannot yet be guaranteed.
